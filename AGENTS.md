# Правила проекта IslandVolt

## Назначение и текущий этап

IslandVolt — расширяемый настольный остров на Rust + GPUI для Windows 10 и 11.
Начат этап 0: прототип Rust + GPUI и проверка Windows-интеграций.

## Зафиксированные решения пользователя

- Целевые ОС: Windows 10 и Windows 11.
- UI: GPUI; основной язык: Rust.
- Речь и ИИ: гибридная модель, локальные и облачные провайдеры по выбору.
- Первый рабочий релиз: основа острова, музыка, громкость, часы и питомец.
- Любой вручную поддерживаемый текстовый файл — максимум 300 строк включительно.
- Функциональные области должны расширяться независимо.
- Нужна коллекция разных анимированных животных внутри острова.

## Архитектурные правила

- Модульный монолит с Cargo workspace; точка сборки зависимостей находится в приложении.
- Доменная логика не зависит от GPUI, Windows API, БД или конкретного ИИ-провайдера.
- GPUI работает в слое представления; системные вызовы — в Windows-адаптерах.
- Фичи обращаются к внешнему миру через узкие типизированные порты.
- Фичи не импортируют внутренние модули друг друга.
- Общее взаимодействие — через команды, события и явно объявленные контракты.
- Не добавлять универсальные менеджеры, глобальное изменяемое состояние или свалку `utils`.
- Не создавать отдельный crate для каждого файла; выделять по зависимости и ответственности.
- Начинать с нужных MVP-модулей. Будущие фичи пока существуют как документация и каталоги.
- Подключаемые возможности сначала компилируемые модули; сторонние плагины отложены.

## Размер и качество файлов

- Предел 300 строк относится к исходникам, тестам, конфигурации и документации.
- При приближении к 250 строкам планировать разделение по самостоятельной ответственности.
- Не ужимать строки, не удалять объяснения и не дробить механически ради лимита.
- Для генерируемого Cargo.lock допускается исключение: пользователь разрешил начать
  реализацию после обсуждения этого исключения. Не править lock-файл вручную.
- После изменений проверять число строк всех затронутых вручную поддерживаемых файлов.
- Публичные контракты документировать; сообщения об ошибках должны объяснять действие пользователя.
- `unsafe` разрешён только на границе FFI, с объяснением инвариантов и минимальной областью.
- Не использовать `unwrap`/`expect` в обработке внешних данных и штатных отказов.
- Для каждой подписки, задачи и нативного ресурса предусматривать отмену и освобождение.

## Асинхронность и ресурсы

- Не выполнять I/O, OCR, модели, кодирование видео и COM-вызовы в UI-потоке.
- Модель исполнения и мост GPUI к фоновым задачам проверяются на техническом этапе.
- Очереди ограничены; частые события объединяются, аудио/видео не идут через UI-шину.
- Остановка фичи отменяет задачи, подписки, таймеры и освобождает устройства.
- Анимации останавливаются при скрытии; поддерживать уменьшенное движение.
- Не опрашивать систему постоянно, если есть подходящие уведомления.

## Данные, облако и управление системой

- Микрофон, захват экрана, история буфера и облачные отправки включаются явно.
- Гибридный режим не означает автоматическую отправку данных в облако при ошибке.
- Секреты хранятся через защищённое хранилище Windows; в логах их быть не должно.
- Не записывать содержимое буфера, заметок, аудио и экрана в диагностические логи.
- ИИ вызывает зарегистрированные типизированные инструменты через проверку разрешений.
- Завершение работы, перезагрузка и другие разрушительные действия требуют подтверждения
  внутри продукта; обычные обратимые действия следуют выбранной политике пользователя.
- Обычный запуск — без прав администратора; недоступная функция получает понятный статус.

## Проверки при реализации

- Форматирование, Clippy и сборка затронутых пакетов перед завершением изменения.
- Тесты для переходов состояния, очереди событий, разрешений, миграций и логики фич.
- Нативные интеграции проверять на Windows 10 и 11, не подменять их одними mock-тестами.
- Для UI проверять DPI, несколько мониторов, фокус, клавиатуру и уменьшенное движение.
- Записывать фактически выполненные проверки; не объявлять неподтверждённую совместимость.
- Зависимости GPUI и Rust фиксировать после проверки совместимой сборки; обновлять осознанно.
- Обновлять связанные документы при изменении границ модулей и поведения.

## Работа с задачами

- Обсуждение и документация — на русском; идентификаторы и имена каталогов — на английском.
- Не считать незакрытый вопрос утверждённым требованием.
- Различать принятое решение, предложение и результат проверки.
- Не обещать точное караоке, поддержку любого приложения или системного API без проверки.
- Новые существенные решения фиксировать в `docs/decisions.md`.
- Имя продукта — `IslandVolt`, префикс Rust-пакетов — `islandvolt-`.
- Основная лицензия — MIT; не переносить её автоматически на сторонние ассеты и модели.

## GitHub и публикация изменений

- Репозиторий: `https://github.com/VoltCoreLabs/IslandVolt`.
- Пользователь разрешил самостоятельно создавать ветки и PR, пушить и мержить изменения
  в рамках согласованных задач. Повторное подтверждение этих действий не требуется.
- Изменения выполнять в тематической ветке, публиковать через PR в `main`.
- Перед merge проверить diff, лимит строк и применимые проверки; дождаться обязательного CI.
- Перед публикацией запускать `python tools/check_repository.py`; CI называется `Repository checks`.
- Параметры репозитория и ограничение защиты `main` описаны в `docs/repository.md`.
- Не обходить защиту веток, не применять force-push и не перезаписывать чужую историю.
- В PR описывать результат, выполненные проверки и существенные ограничения.
- После merge проверить состояние PR и синхронизировать локальный `main`.
- Не коммитить токены, ключи, локальные настройки авторизации и пользовательские данные.
- Пустые каталоги утверждённого каркаса сохранять через `.gitkeep`; при появлении содержимого
  удалять соответствующий placeholder.
