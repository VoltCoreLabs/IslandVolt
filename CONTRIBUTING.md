# Участие в IslandVolt

Проект находится на стадии технического прототипа. Сначала прочитайте
[AGENTS.md](AGENTS.md) и [roadmap](docs/roadmap.md).

## Задачи

Используйте шаблоны GitHub Issues: ошибка, новая возможность или техническая задача.
Указывайте сценарий пользователя, ожидаемый результат и критерии готовности.
В отчётах об ошибках нужны версия Windows, версия приложения и шаги воспроизведения.
Не прикладывайте секреты и содержимое экрана/буфера с личными данными.
Метки `area:*` обозначают область, `priority:*` — приоритет; тип задаётся отдельной меткой.

## Изменения и PR

1. Синхронизировать `main`: `git pull --ff-only`.
2. Создать тематическую ветку: `docs/...`, `feat/...`, `fix/...` или `chore/...`.
3. Внести законченное изменение и обновить связанную документацию.
4. Запустить `python tools/check_repository.py` и `git diff --check`.
5. Создать PR с описанием результата, проверок и существенных ограничений.
6. Дождаться успешного `Repository checks` и применимых проверок приложения.
7. Выполнить squash merge; ветка удалится автоматически.

Один PR решает одну связную задачу. Не использовать force-push и не обходить проверки.
Подтверждение владельца на обычные push/PR/merge уже зафиксировано в правилах проекта.
Для Rust-изменений дополнительно требуются форматирование, Clippy, сборка и необходимые тесты
затронутых пакетов.
Для проверки запуска и штатного выхода используйте `cargo run -p islandvolt-app -- --smoke-test`:
приложение завершится самостоятельно через две секунды. Этот режим не подтверждает клики по UI.

## Файлы и лицензии

Максимум 300 строк в поддерживаемом вручную файле; генерируемый Cargo.lock исключён.
Пустые каталоги сохраняются через `.gitkeep`; удалить placeholder при добавлении содержимого.
Документация — на русском, идентификаторы и каталоги — на английском.
Новые материалы проекта предоставляются на условиях [MIT](LICENSE), если явно не указано иное.
Для сторонних ассетов, шрифтов, моделей и библиотек сохранять исходные лицензии и авторство.
